# shadcn Foundation + Responsive Profile/House/AddExpense Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up a canonical shadcn/ui foundation (RTL-aware, themed from existing Budgetly tokens) and rebuild the Add Expense, Profile, and House Details pages with compact mobile-first responsive layouts.

**Architecture:** shadcn/ui components live in `client/src/components/ui/*`, generated by the shadcn CLI, themed via semantic CSS variables that *reference* existing `--color-*` tokens (dark mode keeps working automatically, nothing hardcoded). Pages keep all hooks/state/logic identical — pure presentation refactors. Old `shared/components/*` stay untouched for other pages.

**Tech Stack:** React 19, Vite 7, Tailwind CSS v4, shadcn/ui (Radix primitives, JS not TS), lucide-react.

**Spec:** `docs/superpowers/specs/2026-08-23-profile-house-addexpense-responsive-design.md`

---

## Deliberate deviations from spec (documented engineering calls)

1. **Avatar picker uses ONE responsive `Dialog`, not Sheet-mobile/Dialog-desktop.** Rendering both would create two simultaneous focus traps. Instead, `DialogContent` gets responsive position classes (bottom sheet + drag handle under `sm:`, centered above). Same UX outcome as spec, single focus trap.
2. **No `--radius-*` theme remapping.** Stock shadcn init remaps `rounded-lg/xl` to a `--radius` scale — that would silently change radii on *every existing page*. We skip it; stock Tailwind radius scale stays untouched app-wide.
3. **Add Expense selects are native `<select>` elements styled directly** instead of the shared `Select` component. The shared component's `size="sm"` hardcodes `text-base` on mobile (iOS-zoom convention we're intentionally moving past on this page per user decision), and its size classes can't be overridden reliably due to Tailwind class-ordering. Still zero Radix Select, per spec.
4. **`useModalA11y` hook removed from ProfilePage** — Radix Dialog provides focus trapping, Escape handling, and aria wiring natively.

## Repo conventions the executor must know

- **Windows / PowerShell.** Chain commands with `;` or run separately — never `&&`.
- All client commands run with `workdir: client`.
- Verification = `npm run lint` (expect: no new errors) + `npm run build` (expect: `✓ built in ...`). There is **no test framework** — do not invent test steps.
- Commit style (from `git log`): `feat(mobile): ...`, lowercase, imperative.
- The app is RTL Arabic. `html[dir="rtl"]` is set in `client/index.html`. Physical classes like `right-2` in existing code are already RTL-correct as-is.
- Dark mode exists via a `.dark` class that redefines `--color-*` tokens. Because our new semantic vars reference those tokens, dark mode needs **zero extra work** — never hardcode hex values in components.

```css
/* ============================
   shadcn/ui semantic theme
   (references Budgetly tokens — dark mode follows .dark automatically)
============================== */
@custom-variant dark (&:is(.dark *));

@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-card: var(--card);
  --color-card-foreground: var(--card-foreground);
  --color-popover: var(--popover);
  --color-popover-foreground: var(--popover-foreground);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-secondary: var(--secondary);
  --color-secondary-foreground: var(--secondary-foreground);
  --color-muted: var(--muted);
  --color-muted-foreground: var(--muted-foreground);
  --color-accent: var(--accent);
  --color-accent-foreground: var(--accent-foreground);
  --color-destructive: var(--destructive);
  --color-border: var(--border);
  --color-input: var(--input);
  --color-ring: var(--ring);
}

:root {
  /* shadcn semantic aliases -> Budgetly tokens */
  --background: var(--color-bg);
  --foreground: var(--color-dark);
  --card: var(--color-surface);
  --card-foreground: var(--color-dark);
  --popover: var(--color-surface);
  --popover-foreground: var(--color-dark);
  --primary: var(--color-primary);
  --primary-foreground: var(--color-on-fill);
  --secondary: var(--color-muted-bg);
  --secondary-foreground: var(--color-dark);
  --muted: var(--color-muted-bg);
  --muted-foreground: var(--color-muted);
  --accent: var(--color-hover);
  --accent-foreground: var(--color-dark);
  --destructive: var(--color-error);
  --border: var(--color-border);
  --input: var(--color-border);
  --ring: var(--color-primary);
  --radius: 1rem;
}
```

Why this is safe despite name collisions (`--color-border` exists in both the project's manual `:root` and our `@theme inline`): the manual `:root` block further down the file is unlayered and therefore wins over Tailwind's layered `@theme` output, so `--color-border` stays `#c3cedd`; the arbitrary-value utilities the app already uses (`border-(--color-border)`) read the variable directly and are unaffected. New semantic utility classes (`bg-background`, `text-primary`, ...) resolve through the chain and land on the correct Budgetly colors.

  const [editingName, setEditingName] = useState(false);

  const [editingEmail, setEditingEmail] = useState(false);

  const handleSaveAvatar = async () => {

  const handleSaveUsername = async () => {
    // Validation
    if (!newUsername || newUsername.trim() === "") {
      toast.warning("اليوزرنيم مينفعش يكون فاضي");
      return;
    }

    if (newUsername.trim() === user.username) {
      setEditingUsername(false);
      return;
    }

    try {
      await updateUsername(newUsername.trim());
      setEditingUsername(false);
    } catch {
      // Error handled in hook
    }
  };

  const handleCancelEdit = () => {
    setNewUsername(user.username);
    setEditingUsername(false);
  };

  const handleSaveName = async () => {
    // Validation
    if (!newName || newName.trim() === "") {
      toast.warning("الاسم مينفعش يكون فاضي");
      return;
    }

    if (newName.trim() === user.name) {
      setEditingName(false);
      return;
    }

    try {
      await updateName(newName.trim());
      setEditingName(false);
    } catch {
      // Error handled in hook
    }
  };

  const handleCancelNameEdit = () => {
    setNewName(user.name);
    setEditingName(false);
  };

  const handleSaveEmail = async () => {

                      إلغاء

                  </h2>
                  <button

                    className="p-1.5 rounded-lg hover:bg-(--color-hover) transition-all text-(--color-primary) cursor-pointer shrink-0"

            <div className="flex items-start gap-2 mb-2">

          <p className="text-xs text-(--color-muted)">جنيه</p>

          </p>

            <p className="text-xs sm:text-sm text-(--color-secondary)">عدد المصاريف</p>
          </div>
          <p className="text-xl sm:text-2xl font-bold text-(--color-dark) font-numbers">
            {stats.expensesCount}
          </p>
          <p className="text-xs text-(--color-muted)">مصروف</p>
        </div>

        <div className="p-4 sm:p-5 rounded-2xl bg-(--color-surface) border border-(--color-border)">
          <div className="flex items-center gap-2 mb-2">

            <div className="flex items-center gap-2 mb-2">

              <p className="text-xs sm:text-sm font-semibold text-(--color-secondary)">
                دفعات منتظرة
              </p>
            </div>
            <p className="text-2xl sm:text-3xl font-bold text-(--color-status-pending) font-numbers">
              {stats.pendingPayments}
            </p>
          </div>

          <div className="p-3 sm:p-4 rounded-xl bg-(--color-bg)">
            <div className="flex items-center gap-2 mb-2">
              <CheckCircle size={16} className="text-(--color-status-approved)" />

              {stats.approvedPayments}
            </p>
          </div>
        </div>
      </div>

      {/* Avatar Selector — bottom sheet on mobile, centered dialog on desktop */}
      <Dialog open={showAvatarModal} onOpenChange={setShowAvatarModal}>
        <DialogContent className={avatarDialogClasses}>
          {/* Mobile drag-handle indicator */}
          <div className="sm:hidden absolute top-2 left-1/2 -translate-x-1/2 w-10 h-1.5 rounded-full bg-(--color-border)" />
          <DialogTitle className="text-base sm:text-2xl font-bold text-(--color-dark) mt-3 sm:mt-0">
            اختر صورة الملف الشخصي

          <DialogDescription className="sr-only">
            اختار من الصور المتاحة تحت دي وصورتك الجديدة هتتحفظ

          <div className="grid grid-cols-4 sm:grid-cols-5 gap-2.5 sm:gap-3 max-h-[50vh] overflow-y-auto custom-scrollbar p-1">
            {availableAvatars.map((avatar) => (
              <button
                key={avatar}
                type="button"
                onClick={() => setSelectedAvatar(avatar)}
                className={cn(
                  "cursor-pointer transition-all hover:scale-105 p-1 rounded-2xl border-2 bg-transparent",
                  selectedAvatar === avatar

            <Button
              onClick={() => setShowAvatarModal(false)}
              variant="outline"
              className="flex-1 min-h-[44px] rounded-2xl font-bold"
            >
              إلغاء
            </Button>
          </div>
        </DialogContent>
      </Dialog>
    </div>
  );
};

export default Profile;
